# EUNOIA Massage — ระบบบริหารร้านนวด

ระบบจัดการคิวหมอนวด รายรับ ส่วนลด ค่าแรง และรายงาน สำหรับใช้งานจริงหน้าร้าน
ออกแบบสำหรับ **iPad / Tablet** เป็นหลัก รองรับ Desktop และมือถือ

**Stack:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Supabase (PostgreSQL + Auth + Realtime)
**Timezone:** Asia/Bangkok · **ภาษา:** ไทยล้วนทั้งระบบ

## ⚡ ติดตั้งแบบรันไฟล์ทีละไฟล์ (ทางเลือก สำหรับคนที่อยากเห็นทุกขั้น)

### 1. สร้างโปรเจกต์ Supabase (ฟรี)

1. เข้า https://supabase.com → **Sign up** → **New project**
2. ตั้งชื่อ `eunoia-massage`, ตั้ง Database Password (เก็บไว้ให้ดี), Region เลือก **Southeast Asia (Singapore)**
3. รอสัก 2 นาทีให้โปรเจกต์สร้างเสร็จ

### 2. สร้างตารางฐานข้อมูล

1. ในโปรเจกต์ Supabase → เมนูซ้าย **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/migrations/001_schema.sql` → **คัดลอกทั้งไฟล์** → วางใน SQL Editor → กด **Run**
   (ถ้าเห็นข้อความ NOTICE สีเหลืองไม่ต้องกังวล — เป็นเรื่องปกติ)
3. ทำซ้ำกับไฟล์ `supabase/migrations/002_seed.sql` → **Run**
   ไฟล์นี้จะใส่รายการบริการทั้ง 12 รายการ + หมอนวดตัวอย่าง 5 คน (แอนนา, เมย์, หนิง, ฝน, จอย)
   + ข้อมูลตัวอย่างของวันนี้ เพื่อให้ทดลอง workflow ได้ทันที
4. ทำซ้ำกับไฟล์ `supabase/migrations/004_group_and_runner.sql` → **Run**
   ไฟล์นี้เพิ่มระบบ **รับลูกค้าเป็นกลุ่ม** และ **หมอวิ่ง**
5. ทำซ้ำกับไฟล์ `supabase/migrations/005_autofinish_edit.sql` → **Run**
   ไฟล์นี้เพิ่ม **ปิดงานอัตโนมัติ** · **หมอวิ่งกดปุ่มเดียว** · **แก้ไขรายการที่ลงผิด**
6. ทำซ้ำกับไฟล์ `supabase/migrations/006_sheets_sync.sql` → **Run**
   ไฟล์นี้เพิ่ม **เซฟรายละเอียดของทุกวันลง Google Sheets**

> **สำคัญ:** ต้องรันตามลำดับ `001` → `002` → `004` → `005` → `006` เสมอ

### 3. เอา Key มาใส่ในโปรเจกต์

1. Supabase → **Project Settings** (รูปเฟือง) → **API**
2. คัดลอก 2 ค่านี้:
   - **Project URL**
   - **anon public** key
3. ในโฟลเดอร์โปรเจกต์ คัดลอกไฟล์ `.env.local.example` เป็น `.env.local` แล้วใส่ค่า:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci....
```

### 4. รันบนเครื่องเพื่อทดลอง

```bash
npm install
npm run dev
```

เปิด http://localhost:3000 → หน้า **เข้าสู่ระบบ** → แท็บ **สร้างบัญชี**

> 🔑 **บัญชีแรกที่สมัคร จะเป็นเจ้าของร้านอัตโนมัติ** (เห็นทุกอย่าง แก้ตั้งค่า ดูการเงิน ยกเลิกรายการได้)
> บัญชีที่สมัครหลังจากนั้นจะเป็น **พนักงานหน้าร้าน**

ถ้า Supabase บังคับยืนยันอีเมล: Supabase → **Authentication → Providers → Email** → ปิด
**Confirm email** (สะดวกกว่าสำหรับใช้งานภายในร้าน)

### 5. Deploy ขึ้นออนไลน์ (Vercel — ฟรี)

```bash
npm i -g vercel
vercel            # ตอบคำถามตามค่า default
vercel --prod
```

ระหว่าง deploy ให้ใส่ Environment Variables 2 ตัวเดียวกับใน `.env.local`
(หรือใส่ทีหลังที่ Vercel → Project → Settings → Environment Variables แล้ว redeploy)

เสร็จแล้วจะได้ลิงก์ เช่น `https://eunoia-massage.vercel.app` → เปิดบน iPad ได้เลย
แนะนำให้กด **Share → Add to Home Screen** บน iPad เพื่อใช้เหมือนแอป

## 🗓️ วิธีใช้งานประจำวัน

| ขั้น | ทำอะไร | หน้าไหน |
|---|---|---|
| 1 | เช้า — ลงชื่อหมอนวดที่มาทำงาน (เรียงตามลำดับที่มา) | **คิววันนี้** |
| 2 | มีลูกค้าเข้า → กด **+ รับลูกค้า** → **ใส่จำนวนลูกค้าก่อน** | **หน้าร้าน** |
| 3 | ระบบวนคิวจ่ายหมอนวดให้ครบทุกคน · คนไม่พอ → **⚡ เรียกหมอวิ่ง** | หน้าต่างรับลูกค้า |
| 4 | กด **เริ่มเดี๋ยวนี้** หรือกำหนดเวลาเอง → ใส่ราคาขายจริง + ค่าแรง | หน้าต่างรับลูกค้า |
| 5 | ครบเวลา — ระบบปิดงานให้เอง แล้วขึ้นในกล่อง *รอเก็บเงิน* (ปิดสวิตช์ได้) | **หน้าร้าน** |

| 7 | เก็บเงิน → กดช่องทางในกล่อง **รอเก็บเงิน** (หรือกด **✓ นวดเสร็จ** เองก่อนครบเวลา) | **หน้าร้าน** |
| 8 | หมอนวดออกไปรับงานร้านอื่น → **ออกไปงานร้านอื่น** / กลับมา → **กลับเข้าคิว** | **คิววันนี้** |
| 9 | ปลายวัน → ตรวจยอด → **ปิดวัน** | **รายงาน / ปิดวัน** |

## 👥 รับลูกค้าเป็นกลุ่ม + หมอวิ่ง

ลูกค้าเดินเข้ามาพร้อมกันหลายคนได้ (มาเป็นครอบครัว / กลุ่มเพื่อน)

1. กด **+ รับลูกค้า** → ขั้นแรกคือ **ใส่จำนวนลูกค้า** (มีปุ่มด่วน 1–6 หรือพิมพ์เอง สูงสุด 12)
2. ระบบ **วนคิวจ่ายหมอนวดให้ครบทุกคนในรอบเดียว** — 1 หมอนวด ต่อ 1 ลูกค้า
   เริ่มนับต่อจากตัวชี้คิวเดิม และคนที่ได้งานในกลุ่มนี้แล้วจะไม่ถูกจ่ายซ้ำ
3. เลือกบริการทีเดียวใช้กับทุกคน แล้ว **แก้รายคนได้** (บริการ ราคาขาย ค่าแรง แยกทุกแถว)
4. **ถ้าหมอนวดในร้านไม่พอ** ระบบจะขึ้นแถบเหลือง "⚡ หมอนวดในร้านไม่พอ — ขาดอีก N คน"
   และแถวที่ยังว่างจะมีปุ่ม **⚡ เรียกหมอวิ่ง**
5. กด **⚡ เรียกหมอวิ่ง** ครั้งเดียวจบ — **ไม่ต้องกรอกชื่อ** ระบบตั้งให้เป็น
   *หมอวิ่ง 1* · *หมอวิ่ง 2* ไล่ไปเรื่อย ๆ และลงคิวต่อท้ายของวันนี้ให้อัตโนมัติ
   (ถ้าอยากใส่ชื่อจริงกด **ระบุชื่อเอง**)
6. บันทึกไม่ได้จนกว่าลูกค้าทุกคนจะมีหมอนวด — หรือลดจำนวนลง แล้วใส่ที่เหลือเข้ารายชื่อรอคิว
7. ปิดงานได้ทั้ง **ทีละคน** หรือ **ทั้งกลุ่มพร้อมกัน** (ปุ่มขึ้นบนหน้าร้านเมื่อมีกลุ่ม)

**เรื่องที่ตั้งใจให้เป็นแบบนี้**

- **หมอวิ่งไม่ขยับตัวชี้คิว** — คิวของหมอนวดประจำจึงไม่เสียลำดับเพราะการเรียกคนนอกมาเสริม
- **การถูกข้ามนับครั้งเดียวต่อกลุ่ม** ไม่ใช่นับทุกคนในกลุ่ม (ไม่งั้นสถิติความยุติธรรมจะเพี้ยน)
- **1 รายการ = 1 ลูกค้า** จึงเห็นได้ว่าหมอนวดคนไหนทำใครไป ค่าแรงตรงคน
- งานของหมอวิ่งถูกทำเครื่องหมายแยก มีคอลัมน์ **งานหมอวิ่ง** ในหน้ารายงาน
- ตั้งใครเป็นหมอวิ่งก็ได้ที่ **ตั้งค่า → หมอนวด → ⚡ เป็นหมอวิ่ง**
  (หมอวิ่งจะไม่ขึ้นในปุ่มลงชื่อเข้าทำงานตอนเช้า — เรียกเฉพาะเวลาต้องใช้)

## ⏱ ปิดงานอัตโนมัติเมื่อครบเวลา

ตั้งค่าได้ที่ **ตั้งค่า → ทั่วไป** (ค่าเริ่มต้น: เปิด)

- ครบเวลาแล้วระบบ **ปิดงานให้เอง** หมอนวดกลับเป็น 🟢 ว่าง ทันที ไม่ต้องกดปุ่ม
- ตั้ง **ผ่อนผัน** ได้ (0 / +5 / +10 / +15 นาที) เผื่อเวลาเก็บของและพาลูกค้าออก
- เวลาที่บันทึกว่า "เสร็จ" คือ **เวลาที่ควรเสร็จจริง** ไม่ใช่เวลาที่ระบบเพิ่งมาเช็กเจอ
  ยอดและรายงานจึงตรงเสมอแม้ไม่มีใครเปิดหน้าจอค้างไว้
- **เรื่องเงิน:** งานที่ปิดอัตโนมัติจะ **ยังไม่ระบุช่องทางชำระ** และไปรออยู่ในกล่อง
  **💰 รอเก็บเงิน** บนหน้าร้าน — กดช่องทางที่รับเงินเพื่อปิดยอด (กดครั้งเดียวจบ)
  ยอดขายนับเข้าแล้ว แต่จะค้างในช่อง "ยังไม่ระบุช่องทางชำระ" ในหน้าการเงินจนกว่าจะกด

> **ถ้าร้านมีลูกค้านวดเกินเวลาบ่อย** ให้ปิดสวิตช์นี้ ระบบจะกลับไปเป็นแบบเดิม คือ
> หมดเวลาแล้วขึ้น "รอกดปุ่มนวดเสร็จ" และหมอนวดยังไม่ว่างจนกว่าจะมีคนกด

## ✏️ แก้ไขรายการที่ลงผิด

หน้า **ประวัติ** → ปุ่ม **แก้ไข** ในแถวนั้น แก้ได้ทุกช่อง:

บริการ · หมอนวด · เวลาเริ่ม · ระยะเวลา · ชื่อลูกค้า · ราคาตั้ง · ราคาขายจริง · ค่าแรง · ช่องทางชำระ

- เลือกบริการใหม่ → ระบบเติมราคาและเวลาของบริการนั้นให้อัตโนมัติ (แก้ทับได้)
- **พนักงานหน้าร้าน** แก้ได้เฉพาะงานที่ยังนวดอยู่ · **เจ้าของร้าน** แก้ได้ทุกงานรวมที่ปิดแล้ว
- เปลี่ยนหมอนวดได้เฉพาะคนที่ลงคิววันนั้น และต้องไม่ติดงานอื่นอยู่ (ระบบกันให้)
- ทุกการแก้บันทึกลง **บันทึกการแก้ไข** ครบทั้งค่าเดิม-ค่าใหม่-ใครแก้-เมื่อไหร่ และขึ้นในไทม์ไลน์
- รายการที่ยกเลิกแล้วแก้ไม่ได้

## 📗 เซฟรายละเอียดของทุกวันลง Google Sheets

### ชีตจะมี 4 แท็บ สร้างให้อัตโนมัติ

| แท็บ | เก็บอะไร |
|---|---|
| **รายการนวด** | ทุกรายการของวัน — รหัส เวลาเริ่ม/เสร็จ หมอนวด บริการ ลูกค้า ราคาเต็ม ราคาที่เก็บจริง ส่วนลด ค่าแรง รายได้ร้าน ช่องทางชำระ หมายเหตุ (รวมรายการที่ยกเลิกพร้อมเหตุผล) |
| **สรุปรายวัน** | บรรทัดเดียวต่อวัน — ยอดขาย ส่วนลดรวม ค่าแรงรวม รายได้สุทธิ เงินสด/QR/บัตร/ยังไม่เก็บเงิน จำนวนงาน จำนวนลูกค้า งานหมอวิ่ง |
| **รายหมอนวด** | ต่อวันต่อคน — จำนวนงาน นาทีที่ทำงาน ยอดขายที่ทำได้ ค่าแรงที่ได้รับ ลูกค้าขอชื่อ ถูกข้ามเพราะไม่ว่าง งานนอกร้าน |
| **ประวัติการส่ง** | ส่งเมื่อไหร่ ของวันไหน กี่รายการ |

2. ในไฟล์นั้น กด **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทิ้ง แล้ววางโค้ดทั้งไฟล์จาก `google-sheets/EUNOIA-AppsScript.gs`
4. แก้บรรทัด `var SECRET = 'eunoia-2026';` เป็นรหัสลับของร้าน (ตั้งเองได้) แล้วกดบันทึก
5. กด **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้ใหม่ → เว็บแอป**
   - ดำเนินการในชื่อ: **ฉัน**
   - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน (Anyone)** ← ถ้าไม่เลือกข้อนี้จะส่งไม่ได้
6. คัดลอกลิงก์ที่ลงท้ายด้วย `/exec`
7. ในโปรแกรม → **ตั้งค่าระบบ → Google Sheets** → วางลิงก์ + รหัสลับเดียวกัน → **บันทึก** → **ทดสอบการเชื่อมต่อ**

### ใช้งานประจำวัน

- **อัตโนมัติ:** กดปิดวันตามปกติ ระบบส่งให้เอง (ปิดสวิตช์นี้ได้ในหน้าตั้งค่า)
- **กดส่งเอง:** หน้า **รายงาน / ปิดวัน** → ปุ่ม **📗 เซฟลง Google Sheets** (ส่งวันไหนก็ได้ที่เลือกอยู่)
- **ตามเก็บย้อนหลัง:** หน้าตั้งค่า → Google Sheets จะขึ้นรายการ **วันที่ยังไม่เคยส่งสำเร็จ** กดส่งทีละวันได้
- **ส่งซ้ำวันเดิมได้** — ระบบจะเขียนทับแถวของวันนั้น ไม่เกิดแถวซ้ำ (เช่น แก้รายการย้อนหลังแล้วส่งใหม่)
- ทุกครั้งที่ส่ง สำเร็จหรือไม่สำเร็จ จะบันทึกไว้ใน **ประวัติการส่ง** ในหน้าตั้งค่า และลบไม่ได้

> ถ้าส่งไม่สำเร็จตอนปิดวัน **ยอดในระบบไม่หายไปไหน** — ข้อมูลหลักอยู่ในฐานข้อมูลเสมอ
> ชีตเป็นสำเนาไว้เก็บและเปิดดูง่ายเท่านั้น กดส่งใหม่ได้ทีหลังเมื่อไหร่ก็ได้

## 🔄 กติกาการวนคิว

ระบบใช้หลัก **วนคิวเป็นรอบ + ข้ามคนที่ยังไม่ว่าง**

1. ลำดับคิวเริ่มต้น = ลำดับที่ลงชื่อเข้าทำงาน (ปรับได้ด้วยลูกศร ▲▼ หรือลากสลับ)
2. ระบบจำ **คนที่ได้รับงานล่าสุด** แล้วเริ่มหาคิวถัดไป **จากคนถัดจากนั้น** — ไม่เริ่มนับ #1 ใหม่ทุกครั้ง
3. ตรวจตามลำดับ ใครสถานะ 🟢 **ว่าง** คนแรก = ได้ลูกค้า
4. ข้ามคนที่ 🔴 กำลังนวด · 🟠 ใกล้เสร็จ · ⚪ พัก · 🟣 งานร้านอื่น · ⚫ เลิกงาน
5. **การถูกข้ามเพราะยังไม่ว่าง ไม่ทำให้เสียคิวถาวร** — ยังอยู่ในรอบเสมอ กลับมาว่างก็ได้คิวตามรอบ
6. ระบบ **ไม่หยุดรอ** คนที่กำลังนวด ถ้ายังมีคนอื่นว่าง
7. ลูกค้าที่อยากรอหมอนวดคนใดคนหนึ่ง → ใส่เข้า **รายชื่อรอคิว** (ไม่กระทบคิวคนอื่น)
8. เลือกหมอนวดเองได้ทุกเมื่อ แต่ **ต้องระบุเหตุผล** และถูกบันทึกในไทม์ไลน์

**สีนับถอยหลัง**

| เหลือ | สถานะ |
|---|---|
| มากกว่า 20 นาที | 🔴 กำลังนวด |
| 11–20 นาที | 🟠 ใกล้เสร็จ |
| 1–10 นาที | 🔴 ใกล้เสร็จมาก (+ ปุ่มต่อเวลาด่วน +30 / +60 นาที) |
| หมดเวลา | 🟢 ปิดงานอัตโนมัติ (หรือ **รอกดปุ่ม “นวดเสร็จ”** ถ้าปิดสวิตช์) |

## 💰 กติกาเรื่องเงิน

- เก็บ **3 ค่าแยกกัน**: `original_price` (ราคาตั้ง — ห้ามเขียนทับ), `final_price` (ราคาขายจริงหลังต่อรอง), `discount` (คำนวณอัตโนมัติ)
- เก็บ **ค่าแรง 2 ค่าแยกกัน**: ค่าเริ่มต้น และค่าที่จ่ายจริง — แก้ได้ทุกรายการ
- **รายได้ร้านสุทธิ = ราคาขายจริง − ค่าแรงที่จ่ายจริง**
- ทุกรายการ **เก็บสำเนาชื่อบริการ ราคา และระยะเวลาไว้ในตัวเอง** → แก้ราคาบริการในอนาคตไม่กระทบรายการเก่า (ทดสอบแล้ว)
- **ลบรายการเงินไม่ได้เลย** — ฐานข้อมูลบล็อกไว้ ต้องใช้ **ยกเลิกรายการ** พร้อมเหตุผล
- รายการที่ยกเลิกไม่รวมในยอด แต่ยังอยู่ในประวัติและบันทึกการแก้ไข
- ทุกการแก้ราคา / ค่าแรง / บริการ / หมอนวด / เวลา ถูกบันทึกใน **บันทึกการแก้ไข** พร้อมค่าเดิม-ค่าใหม่-ใครแก้-เมื่อไหร่ (ทำที่ระดับฐานข้อมูล จึงเลี่ยงไม่ได้)

### ค่าแรงเริ่มต้นที่ตั้งไว้

| บริการ | ราคา | นาที | ค่าแรงเริ่มต้น |
|---|---:|---:|---:|
| นวดหัว | 250 | 30 | 100 |
| นวดเท้า | 300 | 60 | 150 |
| นวดไทย | 300 | 60 | 150 |
| นวดออย | 400 | 60 | 150 |
| คอ บ่า ไหล่ | 500 | 60 | 180 |
| นวดอโลเวร่า | 500 | 60 | 180 |
| นวดอโรม่า | 500 | 60 | 180 |
| นวดน้ำมันมะพร้าว | 500 | 60 | 180 |
| นวดน้ำมันมะพร้าวร้อน | 600 | 60 | 180 ⚠️ |
| ขัดส้นเท้า | 500 | 30 | 100 ⚠️ |
| นวดหน้าและหัว | 800 | 60 | 180 ⚠️ |
| นวดหน้า | — | 30 | ⚠️ **ปิดใช้งานอยู่** |

⚠️ = ค่าแรงของบริการเหล่านี้ไม่ได้ระบุไว้ในข้อกำหนด ผมใส่ค่าที่สมเหตุสมผลไว้ให้ก่อน
**กรุณาตรวจและแก้ที่ ตั้งค่า → บริการ**
สำหรับ **นวดหน้า** ยังปิดใช้งานอยู่ — ให้ตั้งราคาและเวลาก่อน แล้วกด "เปิด"

ค่าแรงยังตั้ง **แยกรายบุคคล** ได้ที่ ตั้งค่า → หมอนวด (ช่องค่าแรง 30 นาที / 60 นาที)

## 📌 หมายเหตุการออกแบบที่ควรทราบ

- **สถานะ Busy / Finishing Soon / Expected Finished ไม่ได้เก็บในฐานข้อมูล** — คำนวณสด ๆ จาก `expected_finish_at` เทียบเวลาปัจจุบัน จึงไม่ต้องมี cron job และไม่มีทางค้างสถานะผิด ฐานข้อมูลเก็บแค่สถานะที่ Admin กดเอง (ว่าง / พัก / งานนอก / เลิกงาน)
- **ช่วง 11–20 นาที** ถูกกำหนดเป็น Finishing Soon (ข้อกำหนดเดิมระบุ 15–20 และ 1–10 ทำให้ช่วง 11–14 ไม่มีสี) — แก้ได้ที่ `statusFromRemaining()` ใน `src/lib/queue.ts`
- **ยอดขายนับเฉพาะรายการที่ปิดงานแล้ว** งานที่กำลังนวดจะแสดงแยกไว้ เพื่อไม่ให้ยอดวันนั้นสูงเกินจริง
- **จำนวนลูกค้ามากกว่า 1 คน** จะคูณทั้งราคาและค่าแรงให้เป็นค่าเริ่มต้น แล้วแก้ทับได้
